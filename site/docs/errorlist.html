Error and warning messages

This is a message reference, not a description of diagnostic categories. {name}, {type}, {value}, and similar placeholders stand for text Lynxer inserts into a message. The set of possible final strings is therefore runtime-dependent. Operating-system, compiler, loader, and native-library messages are supplied by those external components and cannot be listed verbatim here.

Source diagnostics are normally printed as file.lynx:line:column: [diagnosticCode] message. Imported-source errors name the imported file. Lint diagnostics use file.lynx:line:column: error[diagnosticCode]: message or warning[diagnosticCode]: message. Error-code identifiers are stable names for a diagnostic category; names and dynamic values in messages are not part of the code.

The complete builtin API and its argument conventions are in builtins. Native standard-library functions may instead return documented sentinels or error strings; those are listed in stdlib-contracts and the individual module references, and are not necessarily Lynxer diagnostics.

Warnings

  • setup() is optional; no setup() function was declared
  • '{keyword}' function declarations are deprecated; use 'fn'
  • 'class' declarations are deprecated; use 'template'
  • WinAPI built-in calls are deprecated; import the matching winAPI-amd64 or winAPI-arm64 standard library
  • operator '{operator}' is deprecated; use '{replacement}' instead.
  • tuple assigned from a bracketed list is deprecated; use the '(int 1, int 2)' form instead.
  • forever() has no break; it will run until the process is stopped. Add break; or call suppressForeverWarning() in fn setup(){}.
  • unused parameter '{name}'
  • unused variable '{name}'
  • unused method parameter or variable '{name}'
  • unreachable statement
  • {subject} converts '{actual}' to '{expected}'; the value may be rejected or lose information at runtime

Deprecation warnings can be suppressed with suppressDeprecationWarning() in setup() for runtime warnings. Parser-time warnings, including deprecated function declarations, are emitted while parsing and cannot be suppressed by that function. The no-break warning can be suppressed with suppressForeverWarning() in setup(). Lint warnings are not suppressed by these functions.

Standard-library returned errors

These are returned by APIs rather than raised as Lynxer runtime errors:

  • Error: node not found on PATH
  • Error: node timed out after {seconds}s
  • Error: node exited with status {status}
  • ERROR: could not read '{path}'
  • ERROR: rows must be a JSON array
  • ERROR: rows must be a JSON array of objects
  • ERROR: could not write '{path}'
  • ERROR: write failed
  • ERROR: row must be a JSON array

Other modules return their documented scalar/status sentinels or backend error text; consult the module-specific references for those results.
