Bob — the package manager

Bob is the package manager for the Lynxer language, named after the bobcat — a species of lynx. It is a standalone Rust component that lives in Bob/, deliberately kept separate from the interpreter: it has its own Makefile and version and only knows which Lynxer version it supports.

Bob scaffolds a project or a reusable module, publishes a module to a GitHub Release, and installs a module by resolving its name through the Bob registry. See bob-modules for the module format and bob-registry for the registry.

Build it with make buildBob (or make -C Bob) and run Bob/target/release/bob.

Commands

CommandEffect
bob --verPrints the Bob version and the Lynxer version it supports.
bob --initCreates bob/bob.toml, bob/bob-lock.toml and an empty bob/packages/.
bob --init --moduleCreates module.toml and src/main.lynx in a reusable module project.
bob publishValidates the current module, packages it as a ZIP, and uploads it as a GitHub release asset.
bob install <name> <version>Resolves a package and downloads its release asset.
bob registry add|list|configManage local package→repository mappings in ~/.bob/registry.json.
bob config set|get|show|unset|pathManage ~/.bob/config.json (registry link and GitHub token).
bob --helpUsage.
$ bob --ver
bob 0.1.0
supported lynxer 0.1.8.2

$ bob --init
Created bob/bob.toml
Created bob/bob-lock.toml
Created bob/packages/

$ bob --init --module
Created module.toml
Created src/main.lynx

Configuration

Bob reads two settings, stored in ~/.bob/config.json:

KeyMeaning
rest-apiBase link of the Bob REST registry (for example https://lynxer.netlify.app). Resolves a package name to its GitHub repository.
github-tokenGitHub API token used to create releases (publish) and download assets (install).
$ bob config set rest-api https://lynxer.netlify.app
$ bob config set github-token ghp_...
$ bob config show
rest-api = https://lynxer.netlify.app
github-token = ghp_****
config file: /home/you/.bob/config.json

bob config get <key> prints one value (the token is masked), bob config unset <key> removes one, and bob config path prints the file location. On Unix the file is written with 0600 permissions because it can hold a token.

Each setting can be overridden by an environment variable, which takes precedence over the file: BOB_REST_API for the registry link and GITHUB_TOKEN for the token. BOB_CONFIG_DIR overrides the directory that holds config.json (default ~/.bob).

Project layout

A Bob application keeps its manifest and lock file under a single bob/ directory:

bob/bob.toml        the manifest ([package], [dependencies])
bob/bob-lock.toml   the lock file, generated by Bob
bob/packages/       downloaded package archives

bob/bob.toml and bob/bob-lock.toml use the same TOML model Cargo uses.

Publish and install

bob publish reads module.toml, packages manifest.toml alongside src/ into a ZIP, creates a GitHub release tagged with the module version, and uploads the archive as {name}-{version}.zip. bob install <name> <version> resolves the package to a GitHub repository, downloads the matching release asset into bob/packages/{name}-{version}/, and reports its SHA-256. The archive format and validation are described in bob-modules.

Both need a GitHub token (from github-token or GITHUB_TOKEN). Tokens are sent only to GitHub over HTTPS, never to the registry; never put a token in module.toml.

Status. bob install currently writes the download to bob/packages/{name}-{version}/archive.zip; extracting it into modules/<name>/ so the interpreter can import it is planned (see ../Bob/todo).

Platform and CI

Bob builds for Linux, macOS and Windows. On Windows it uses a static CRT, so bob.exe is standalone and runs from cmd.exe or PowerShell. Bob has its own CI, separate from the Lynxer jobs: build-bob-{amd,arm,windows-amd,windows-arm}.yml build and self-check it, scoped to Bob/**.
