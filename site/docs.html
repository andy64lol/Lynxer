Getting started

Build the interpreter and every native module from a checkout:

make                    # interpreter + native (C++ and Rust) modules
./lynxer/lynxer prog.lynx
./lynxer/lynxer --compile prog.lynx -o prog   # standalone executable
./prog

cargo is optional: without it the Rust-backed modules are skipped with a warning and everything else still builds. The interpreter runs on Linux, on amd64 and ARM64.

Command line

CommandWhat it does
lynxer <file.lynx>Run a source file
lynxer --no-opt <file.lynx>Run without the AST optimizer
lynxer --lint <file.lynx>Check syntax without running
lynxer --ast <file.lynx>Print the abstract syntax tree
lynxer --format <file.lynx>Rewrite a file with canonical spacing
lynxer --format-oneline <file.lynx>Collapse a file onto one line
lynxer --compile <a.lynx> [-o name]Build a standalone executable (--bundle is an alias)
lynxer --validate-executeableRun the interpreter self-check
lynxer --list-stdlibsList the available standard-library modules
lynxer --version / --helpVersion and usage
lynxer --install / --uninstallCopy or remove /usr/bin/lynxer

--compile embeds the program, every transitively imported .lynx module and every imported native .so. Extra --include <file> inputs become importable modules or data assets readable with bundledFile(). The output name comes from -o/--name, or defaults to the first input without its .lynx extension.

Program structure

A program declares global setup() first and global main() last. setup() is where imports and constants live; main() is the entry point. 

global setup(){
    importAs("math", "m");
    const str LANG = "Lynxer";
}

global main(){
    println("Hello, ", LANG, " ", m.sqrt(144));
}

Types

TypeNotes
int, floatNumeric types
str, boolText and boolean
anyHolds a value of any type
list, tupleOrdered collections with their own builtins
sentinelIdentity-comparable marker values
codeblockA stored block of statements, run with exec

Declarations are typed and may be const. Fixed-width integer and float types are also available; see the full type reference.

Control flow

if (x > 10) { println("large"); }
elif (x > 5) { println("medium"); }
else { println("small"); }

while (x > 0) { x -= 1; }
for (int i = 0; i < 5; i = i + 1) { println(i); }
doWhile (x < 3) { x += 1; }
iterate 3 { println("tick"); }
forever { break; }

switch (x) {
    case 1 { println("one"); }
    default { println("other"); }
}

try { int z = 1 /% 0; } catch (str error) { println(error); }

break, continue and restart control loops. Word operators are canonical (and, or, not, is, isnt, bitand, …); floor division is /% and exponentiation ^.

Functions and codeblocks

global greet(str who) -> str { return "Hello, " + who; }
func helper(int a) -> int { return a + 1; }   // file-wide

global main(){
    local doubleIt(int a) -> int { return a * 2; }
    println(greet("Lynxer"), " ", doubleIt(21));
}

codeblock hello = { println("hi"); };
exec(){{hello}}

Parameters may have types and defaults, return types are optional, and functions can be passed around as codeblock values.

Structs, classes and enums

struct Point { int x; int y; }
vargroup Player { str name = "Ada"; int score = 0; }
class Counter { int value = 0; local inc() -> int { this.value += 1; return this.value; } }
enum status = [ Ready, Failed(str reason) ]{}

Enums are tagged unions with payloads and switch pattern matching; structs and vargroups are typed records; classes add fields and local methods.

Modules

import("math");               // global.math.sqrt(...)
importAs("os", "operating");  // global.operating.getcwd()

Modules are .lynx files exposing functions under a namespace, or native .so backends behind the same import surface.

Standard library

Lynxer ships 27 modules, each with a native backend:

AreaModules
Core and utility math, random, time, sys, os, path, fileIO, text, typing, debug, colorlib, cli, shell
Data and text json, csv, re, regex, sqldb, lua, js
Systems and network multiprocessing, network, server
Media and interaction image, sound, game, tui

lynxer --list-stdlibs prints the modules present next to the interpreter, with their docstrings.

Native modules

A native module is a shared library that registers operations through one frozen C ABI (lynxer_module_init_v1). The same ABI is used by the C++ backends in lynxer/stdlib/*.cpp and the Rust crates under lynxer/rust/, and an optional host API (lynxer_module_attach_v1) lets a module call back into Lynxer.

See the native-module ABI and extending guide.

Limitations and non-goals

Some features are deliberately not implemented. These are permanent non-goals:

Not plannedWhy
Bytecode (the .lynxc format)Replaced by standalone --compile executables
rawPy / Python embeddingLynxer has no Python runtime
tkinter, turtleNo Python GUI toolkit; a future GUI would be Rust-backed
http / net modulesReplaced by network + server
Click / Typer buildersThe cli module does not depend on them
Python runtime introspectionThere is no Python runtime to introspect
async* built-insNo async language support or event loop
/* ... */ comments, bare !, \x/\u escapesNot part of the grammar

Other behaviour is implemented but constrained — see the full limitations register.
